#### 1. Общий Обзор Документов
- **Статьи (Multipath_Transaction_on_radar_system_as_papers_13_08_2025.docx и jamming_paper_v2.docx):**
  - Первая статья фокусируется на multipath detection в автомобильных радарах (MIMO антенны, steering vectors, projection matrix для метрики различения real/ghost targets). Упоминает метрику на основе нормы сигнала после проекции на ортогональное подпространство (Wiener-Hopf для jamming suppression). Данные: открытый датасет с AWR1843 (8 виртуальных антенн).
  - Вторая – о jamming/spoofing атаках, подавлении помех Wiener-Hopf. Подчёркивает важность сохранения фазы в предобработке, нормализации по мощности, оценку корреляционной матрицы помехи (N=64 отсчётов).
  - Ключ: Данные – комплексные векторы (каналы MIMO), метрики (mb_metrix для multipath), углы (DOA в азимуте). Подавление помех – критично для низкого SNR.

- **Синтетические данные (dataset.py):**
  - Генерирует данные для 12 антенн (MIMO: 3 Tx + 4 Rx = 12 виртуальных).
  - Функции: `dataset_gen_2D` (с шумом), `dataset_gen_2D_clean` (фильтрованный по mb_metrix <0.8 для multipath), `math_classificator` (бинарный: 0=direct, 1=multipath на основе порога 0.8).
  - Выход: sig_mimo [N,12,1] комплексный, metrix (классы), mb_metrix (норма проекции).
  - Нормализация: По норме (L2) или max(abs) – правильно для фазы (сохраняет относительные фазы).
  - Проблемы: Жёстко на 12 антенн, случайные азимуты (±90°), шум ~0.2*randn – не полностью имитирует реальные (AWR1843: 8 антенн, реальные jamming/multipath).

- **Реальные данные (.txt файлы, e.g., 2019_04_30_cm1s000.txt, etc.):**
  - Формат: Каждая строка – измерение: [ID] [frame] [time] [8 комплексных каналов (real+imag)] [3 метрики?] [2 азимута?] [класс (0/1/2?)].
  - Пример: 254 14 3.134... [комплексные числа] ... 1 (класс?).
  - 8 каналов (AWR1843: 2 Tx + 4 Rx = 8 виртуальных).
  - Классы: 0=direct, 1=multipath, 2=two targets (как в 3-классовом скрипте).
  - Проблемы: Разный SNR, jamming (шум в полосе), multipath. Нужно калибровать фазы/амплитуды (из-за антенн), нормализовать по RMS/power (не max, чтобы не искажать фазу).

- **Скрипты классификации:**
  - NN_multipath_complex_v3.py: Бинарный классификатор (ComplexNet) на синтетике (12 антенн), BCE loss.
  - NN_multipath_complex_3_classes_on_real_data.py: 3-классовый на реальных (8 антенн), но использует BCE (ошибка для multi-class!), CrossEntropy нужен.

- **study_for_paper_v1.py:** Описания 4 подходов (Siamese, LISTA, Cov Recon, Hier GRU) + код пайплайнов. Обрезан, но фундаментальная ошибка в Siamese (как указано: неправильные данные/предобработка).

Предыдущая модель права на ~85-90%: Её выводы точны по ошибкам, но чуть преувеличены (e.g., не все функции отсутствуют). Детали:

  - Подавление jamming: Wiener-Hopf (как в статье) – идеально (оценка cov матрицы по N=64 чистым отсчётам, whitening).

  - LISTA/OMP unfolded: Physics-informed для sparse DOA (как OMP в статье).
  - Covariance Reconstruction: Для multipath filtering (Root-MUSIC benchmark).
  - Hierarchical GRU: Для sequential data (frames).

#### 2. Детальный Разбор 4 Методов
Файл структурирован по 4 подходам. Каждый включает: преимущества/недостатки, когда использовать, ожидаемые результаты, пайплайн (data prep, preprocessing, training, inference, evaluation). Они ориентированы на твои задачи (multipath detection via projection matrix, jamming via Wiener).

##### Метод 1: Siamese / Contrastive сеть + sparse augmentation
- **Описание**: Контрастивное обучение для эмбеддингов сигналов. Пары: Положительные (вариации одного DOA с шумом/прореживанием каналов), отрицательные (разные DOA). Sparse augment имитирует jamming/неисправности антенн.
- **Преимущества**: Устойчивость к низкому SNR (0–10 dB), multipath (multilabel выход), jamming (augment маскирует). Self-supervised, меньше labeled data. Интеграция с math_classificator.
- **Недостатки**: Генерация пар увеличивает время. Менее интерпретируемо. Fine-tune на реальных (TI AWR1843) нужен.
- **Когда использовать**: Основной для студента (баланс perf/ресурсов).
- **Ожидаемые результаты**: Synth: acc>95% по DOA (±1°), F1>0.9 по multipath. Real: +20–30% vs OMP.
- **Пайплайн**:
  - Data prep: Синтетика/реальные из dataset.py. Пары с augment (noise, 20–40% прореживание, phase shifts для антенн ошибок). Labels: DOA-grid (-90°..90°, шаг 1°), multipath class (из metrix), num sources.
  - Preprocessing: Wiener-Hopf jamming suppression, multipath filter via math_classificator.
  - Training: Contrastive loss на эмбеддингах + BCE на DOA/multilabel. AdamW, lr=1e-4, epochs=50–100.
  - Inference: Эмбеддинг → DOA по пикам.
  - Evaluation: RMSE/F1 на synth/real.
- **Связь с данными**: Sig_mimo (complex vectors) для пар. Реальные: каналы после load_real_data.

##### Метод 2: LISTA (Learned Iterative Shrinkage-Thresholding Algorithm) или OMP unfolded
- **Описание**: "Развёртывание" OMP (Orthogonal Matching Pursuit) в нейросеть для sparse DOA (как в multipath статье). Physics-informed (учитывает steering vectors).
- **Преимущества**: Интерпретируемо ( OMP-like), хорошо для sparse сигналов (few targets). Устойчив к multipath via thresholding.
- **Недостатки**: Требует знания модели (e.g., антенн геометрия). Меньше гибкости для сильного шума.
- **Когда использовать**: Для точного DOA в sparse сценариях (1-2 targets).
- **Ожидаемые результаты**: RMSE ~0.5° на synth, улучшение vs классический OMP на real.
- **Пайплайн**:
  - Data prep: Синтетика с sparse labels (num targets ≤2). Реальные с azimuth.
  - Preprocessing: Wiener для jamming.
  - Training: Unfold OMP iterations в слои (thresholding как soft-shrinkage). Loss: MSE по DOA + sparsity regularizer.
  - Inference: Итеративный вывод DOA.
  - Evaluation: RMSE vs ground truth (azimuth в данных).
- **Связь с данными**: OMP_FFT из dataset.py как baseline.

##### Метод 3: Covariance Reconstruction
- **Описание**: Реконструкция ковариационной матрицы (cov matrix) для multipath filtering (e.g., Root-MUSIC для DOA). Использует projection matrix (как в multipath статье).
- **Преимущества**: Эффективно для multipath (residual metric >0.8 для ghosts). Интегрирует Wiener-Hopf.
- **Недостатки**: Вычислительно интенсивно (cov estimation по N=64). Менее robust к сильному шуму без NN.
- **Когда использовать**: Для benchmark vs math_classificator.
- **Ожидаемые результаты**: F1>0.9 по multipath, RMSE <2° после filtering.
- **Пайплайн**:
  - Data prep: Cov по snapshots (K=64).
  - Preprocessing: Whitening (inv cov) для jamming.
  - Training: NN для cov denoising (e.g., autoencoder) + multilabel loss.
  - Inference: Recon cov → eigendecomp → DOA peaks.
  - Evaluation: Detection rate ghosts vs real targets.
- **Связь с данными**: Mb_metrix для residual, cov в wiener_hopf_whiten.

##### Метод 4: Hierarchical GRU
- **Описание**: Иерархическая рекуррентная сеть (GRU) для sequential data (frames over time). Нижний уровень: Каналы → features; верхний: Sequence → DOA/multipath.
- **Преимущества**: Учитывает temporal dynamics (moving targets). Хорошо для real data (frames как в .txt).
- **Недостатки**: Требует последовательных данных (doppler/range bins). Overfit на small datasets без augment.
- **Когда использовать**: Для видео-like данных (e.g., frame_100 в скриптах).
- **Ожидаемые результаты**: Acc>90% по классам, RMSE ~1° на sequences.
- **Пайплайн**:
  - Data prep: Sequences по frames (doppler_bin/range).
  - Preprocessing: Normalize + Wiener.
  - Training: Hierarchical: Conv1D/GRU на channels → GRU на seq. Loss: CE + MSE DOA.
  - Inference: Seq input → predicted DOA trajectory.
  - Evaluation: Temporal metrics (tracking error).
- **Связь с данными**: Range/doppler из .txt для seq.

### 1. wiener_hopf_whiten (Винеровская отбеливающая фильтрация)

**Что это такое?**  
Функция, которая оценивает ковариационную матрицу шума/помех по первым K снимкам (обычно K=64) и применяет обратную матрицу к сигналу:  
`whitened = R⁻¹ @ signal`

**Зачем нужна?**  
- Подавляет **jamming** (целенаправленные помехи) и коррелированный шум.  
- Убирает влияние сильных отражений/мультипаса на оценку DOA.  
- Улучшает работу последующих методов (OMP, MUSIC, нейросеть).

**Что даёт?**  
- Существенно повышает точность DOA при наличии jamming (часто +20–40% по RMSE).  
- Делает данные «белыми» (uncorrelated noise) → лучше работает BatchNorm, Conv1d, contrastive loss.  
- Критично для реальных данных AWR1843 (много отражений от дороги, машин, зданий).

**Почему минус в скриптах другого программиста?**  
Без whitening модель видит «грязный» сигнал → хуже классификация multipath и выше RMSE по углам.

### 2. rms_normalize (нормализация по RMS мощности) vs только max norm

**Что такое rms_normalize?**  
`channels = channels / sqrt(mean(|channels|²))`  
Нормализует каждый сэмпл по его собственной средней мощности (RMS).

**max norm (что используется в скриптах другого программиста):**  
`channels = channels / max(abs(channels))`  
Нормализует по максимальному амплитудному значению.

**Зачем нужна rms_normalize?**  
- Сохраняет **относительные амплитуды** между антеннами (важно для steering vector и DOA).  
- Более устойчива к одиночным выбросам/пикам (max norm может «сдавить» слабые сигналы).  
- Лучше для низкого SNR и многолучёвости (сохраняет энергетический баланс).

**Что даёт rms_normalize?**  
- Стабильнее работает комплексная свёртка и BatchNorm.  
- Лучше сохраняет фазовую информацию (критично для DOA).  
- Улучшает обобщение модели на реальные данные с разной мощностью сигналов.

**Почему max norm хуже?**  
Может сильно искажать слабые каналы, если в одном канале сильный пик (типично при multipath или jamming).

### 3. Расширенный math_classificator (только projection vs полный residual/projection)

**Что такое math_classificator в твоём варианте?**  
Поддерживает два режима:
- `'residual'` → `residual = sqrt(max(0, 1 - proj²))`
- `'projection'` → `proj = |<A, sig>| / ||sig||`

**Что в скриптах другого программиста?**  
Только projection (`if mb_metrix_mb < 0.8`).

**Зачем нужен residual mode?**  
- Residual лучше отражает **отклонение** от идеального steering vector (более чувствителен к multipath).  
- Позволяет гибко выбирать порог в зависимости от задачи (residual лучше для сильного multipath).

**Что даёт расширенный вариант?**  
- Более точная и интерпретируемая классификация multipath (можно выбрать лучший режим под данные).  
- Легче калибровать порог 0.8 под разные SNR/сценарии.  
- Позволяет использовать обе метрики одновременно (residual + projection).

**Почему только projection — минус?**  
Менее гибко, хуже работает при сильном coherent multipath (residual чувствительнее).

### 4. Placeholder mb_metrix = 10 zeros

**Что это такое?**  
В твоём `load_real_data` для каждого реального сэмпла добавляется `np.zeros(10)` в `mb_metrix`.

**Зачем нужен?**  
- Сохраняет **единую форму данных** между синтетикой и реальными данными.  
- Синтетика возвращает `mb_metrix` размерности [N,] или [N, K] (результаты OMP_FFT).  
- Реальные данные из .txt не содержат mb_metrix (или содержат только 3 значения).  
- Placeholder позволяет **одним кодом** обрабатывать оба типа данных (например, в пайплайнах, где ожидается определённая размерность).

**Что даёт?**  
- Избегает ошибок размерности при смешивании синтетики и реальных данных.  
- Упрощает код в моделях/потерях (не нужно писать if real else synth).  
- Легко заменить на реальные значения позже (например, после OMP_FFT на реальных данных).

**Почему отсутствие — минус?**  
Может привести к ошибкам формы при переходе от синтетики к реальным данным.

### Зачем whitening нужен на синтетике?

1. **Уменьшить domain gap (разрыв между синтетикой и реальностью)**  
   - Без whitening: синтетика → белый шум.  
   - Реальные данные → отбеленный сигнал (ковариация близка к единичной матрице).  
   - Результат: модель, обученная только на синтетике, хуже переносится на реальные данные (domain shift).  
   → Whitening на синтетике делает распределения данных **ближе**.

2. **Имитировать реальный preprocessing пайплайн**  
   Ты уже применяешь whitening ко всем реальным данным (train/validate/test).  
   Чтобы модель видела **одинаковый тип предобработки** на pretrain и fine-tune, нужно применять whitening и к синтетике.

3. **Улучшить conditioning матрицы и сходимость сети**  
   - После whitening ковариационная матрица приближается к I (единичной).  
   - Это улучшает числовую стабильность комплексных свёрток, BatchNorm, contrastive loss и т.д.

4. **Лучше тестировать robustness к jamming**  
   Даже если в синтетике нет сильного jamming, whitening позволяет **имитировать** эффект подавления коррелированных помех — это полезно для проверки устойчивости модели.

5. **Согласованность с math_classificator и residual_metric**  
   Projection/residual метрики работают лучше на "отбеленных" сигналах (меньше влияния корреляций).

### Когда whitening на синтетике можно пропустить?
- Если ты обучаешь модель **только на синтетике** и никогда не делаешь fine-tune на реальных данных.
- Если хочешь протестировать модель в "идеальных" условиях (только белый шум).

import numpy as np
import os

def wiener_hopf_whiten(channels, K=64, eps=1e-6):
    """Wiener-Hopf whitening (как в твоём preprocess)"""
    if channels.ndim != 2:
        channels = channels.squeeze(-1)  # [N, M, 1] -> [N, M]
    N, M = channels.shape
    K = min(K, N)
    cov = np.zeros((M, M), dtype=np.complex64)
    for i in range(K):
        x = channels[i]
        cov += np.outer(x, np.conj(x))
    cov /= max(K, 1)
    R_inv = np.linalg.inv(cov + eps * np.eye(M))
    return (R_inv @ channels.T).T  # [N, M]

def rms_normalize(channels, eps=1e-12):
    """RMS нормализация (лучше max)"""
    power = np.mean(np.abs(channels) ** 2, axis=1, keepdims=True)
    return channels / np.sqrt(power + eps)

# === 2. Расширь math_classificator ===
def math_classificator(metrix, mode='residual', threshold=0.8):
    y_pred = np.zeros([len(metrix), 1], dtype=int)
    if mode == 'projection':
        ids = np.where(metrix < threshold)
    else:  # residual (по умолчанию)
        ids = np.where(metrix > threshold)
    y_pred[ids, :] = 1
    return y_pred

import argparse
import numpy as np
import torch
import torch.nn as nn

from dataset import dataset_gen_final_experiment, wiener_hopf_whiten, rms_normalize  # ← добавлено

class ComplexNet(nn.Module):
    def __init__(self, input_length=8, oconv1_ch=4, conv1_k=3, oconv2_ch=8, conv2_k=3,
                 oconv3_ch=16, conv3_k=3, ofl=32):
        super().__init__()
        self.conv1 = nn.Conv1d(1, oconv1_ch, conv1_k, dtype=torch.complex64)
        self.conv2 = nn.Conv1d(oconv1_ch, oconv2_ch, conv2_k, dtype=torch.complex64)
        self.conv3 = nn.Conv1d(oconv2_ch, oconv3_ch, conv3_k, dtype=torch.complex64)

        self.bn1 = nn.BatchNorm1d(oconv1_ch)
        self.bn2 = nn.BatchNorm1d(oconv2_ch)
        self.bn3 = nn.BatchNorm1d(oconv3_ch)
        self.ap = nn.AvgPool1d(2)
        self.relu = nn.ReLU()
        self.dropout = nn.Dropout(0.5)

        conv3_out = ((input_length - conv1_k + 1) - conv2_k + 1) - conv3_k + 1
        apool = conv3_out // 2
        self.flattened_size = oconv3_ch * apool

        self.fc1 = nn.Linear(self.flattened_size, ofl)
        self.fc2 = nn.Linear(ofl, 3)

    def forward(self, x):
        x = torch.tanh(self.conv1(x))
        x = torch.complex(self.bn1(x.real), self.bn1(x.imag))

        x = torch.tanh(self.conv2(x))
        x = torch.complex(self.bn2(x.real), self.bn2(x.imag))

        x = torch.tanh(self.conv3(x))
        x = torch.complex(self.bn3(x.real), self.bn3(x.imag))

        x = x.abs()
        x = self.ap(x)
        x = x.reshape(x.size(0), self.flattened_size)
        x = self.fc1(x)
        x = self.relu(x)
        x = self.dropout(x)
        return self.fc2(x)


def to_complex_tensor(X):
    X_re = torch.FloatTensor(np.real(X)).permute(0, 2, 1)
    X_im = torch.FloatTensor(np.imag(X)).permute(0, 2, 1)
    return torch.complex(X_re, X_im)


def train_model(model, X, y, epochs=40, batch_size=512, lr=1e-3):
    optimizer = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=1e-4)
    criterion = nn.CrossEntropyLoss()
    model.train()
    for epoch in range(epochs):
        for i in range(0, len(X), batch_size):
            X_batch = X[i:i + batch_size]
            y_batch = y[i:i + batch_size]
            outputs = model(X_batch)
            loss = criterion(outputs.float(), y_batch)
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
        if (epoch + 1) % 5 == 0:
            print(f"Epoch {epoch+1}/{epochs} | Loss: {loss.item():.4f}")


def main():

class ComplexNet(nn.Module):
    def __init__(self, input_length=8, oconv1_ch=4, conv1_k=3,
                 oconv2_ch=8, conv2_k=3, oconv3_ch=16, conv3_k=3, ofl=64):
        super().__init__()
        self.conv1 = nn.Conv1d(1, oconv1_ch, conv1_k, dtype=torch.complex64)
        self.conv2 = nn.Conv1d(oconv1_ch, oconv2_ch, conv2_k, dtype=torch.complex64)
        self.conv3 = nn.Conv1d(oconv2_ch, oconv3_ch, conv3_k, dtype=torch.complex64)

        self.bn1 = nn.BatchNorm1d(oconv1_ch)
        self.bn2 = nn.BatchNorm1d(oconv2_ch)
        self.bn3 = nn.BatchNorm1d(oconv3_ch)
        self.ap = nn.AvgPool1d(2)
        self.relu = nn.ReLU()
        self.dropout = nn.Dropout(0.5)

        conv3_out = ((input_length - conv1_k + 1) - conv2_k + 1) - conv3_k + 1
        apool = conv3_out // 2
        self.flattened_size = oconv3_ch * apool

        self.fc1 = nn.Linear(self.flattened_size, ofl)
        self.fc2 = nn.Linear(ofl, 3)

    def forward(self, x):
        x = complex_tanh(self.conv1(x))
        x = torch.complex(self.bn1(x.real), self.bn1(x.imag))

        x = complex_tanh(self.conv2(x))
        x = torch.complex(self.bn2(x.real), self.bn2(x.imag))

        x = complex_tanh(self.conv3(x))
        x = torch.complex(self.bn3(x.real), self.bn3(x.imag))

        x = x.abs()
        x = self.ap(x)
        x = self.dropout(x)
        x = x.reshape(x.size(0), self.flattened_size)
        x = self.fc1(x)
        x = self.relu(x)
        x = self.dropout(x)
        return self.fc2(x)

import numpy as np
import matplotlib.pyplot as plt

# ======================== НОВЫЕ ФУНКЦИИ ========================

def wiener_hopf_whiten(channels, K=64, eps=1e-6):
    """Wiener-Hopf whitening (как в preprocess_real_data.py)"""
    if channels.ndim == 3 and channels.shape[-1] == 1:
        channels = channels.squeeze(-1)  # [N, M, 1] -> [N, M]
    N, M = channels.shape
    K = min(K, N)
    cov = np.zeros((M, M), dtype=np.complex64)
    for i in range(K):
        x = channels[i]
        cov += np.outer(x, np.conj(x))
    cov /= max(K, 1)
    R_inv = np.linalg.inv(cov + eps * np.eye(M))
    return (R_inv @ channels.T).T  # [N, M]


def rms_normalize(channels, eps=1e-12):
    """RMS нормализация (рекомендуется вместо max)"""
    if channels.ndim == 1:
        channels = channels[None, :]
    power = np.mean(np.abs(channels) ** 2, axis=1, keepdims=True)
    normalized = channels / np.sqrt(power + eps)
    return normalized.squeeze(0) if channels.shape[0] == 1 else normalized


def math_classificator(metrix, mode='residual', threshold=0.8):
    """
    Расширенная версия:
    mode='residual'  →  residual = sqrt(max(0, 1 - proj²))
    mode='projection'→  proj < threshold
    """
    y_pred = np.zeros([len(metrix), 1], dtype=int)
    if mode == 'projection':
        ids = np.where(metrix < threshold)[0]
    else:  # residual (по умолчанию)
        ids = np.where(metrix > threshold)[0]
    y_pred[ids, :] = 1
    return y_pred

def plot_DOA(sig, step):
    angle_arr = np.arcsin(np.linspace(-512, 511, 1024)/1024/step)
    ch_wide = np.zeros(1024, dtype=complex)
    ch_wide[0:len(sig)] = sig
    plt.plot(angle_arr*180/np.pi, abs(np.fft.fftshift(np.fft.fft(ch_wide))))
    return 0


def OMP_FFT(idat, ch_loc, N_fft, iternum):
    dat_ind = (ch_loc/0.5).astype(int)
    osig = np.reshape(idat, [1, len(idat)])
    dat_w = np.zeros([1, N_fft], dtype=complex)
    angle_arr = np.arcsin(np.linspace(-N_fft/2, N_fft/2-1, N_fft)/(0.5*N_fft))
    dat_norm = np.zeros(iternum)
    oangle = np.zeros(iternum)
    for i in range(iternum):
        dat_w[0, dat_ind] = osig
        DOA = np.fft.fft(dat_w)
        max_id = np.argmax(abs(DOA))
        amp = DOA[0, max_id]/len(idat)
        osig = osig - amp*np.exp(-1j*2*np.pi*dat_ind*(N_fft - max_id)/N_fft)
        dat_norm[i] = np.linalg.norm(osig)/np.linalg.norm(idat)
        max_id = np.argmax(np.fft.fftshift(abs(DOA[0, :])))
        oangle[i] = angle_arr[max_id]
    return oangle, dat_norm

def dataset_from_real_data(path, normalize='rms'):
    """
    normalize='rms' (рекомендуется) или 'max' или 'none'
    """
    files = sorted([f for f in os.listdir(path) if f.endswith('.txt')])
    exp_dataset = {
        'doppler bin': [], 'range bin': [], 'range': [],
        'channels': [], 'mb_metrix': [], 'azimuth': [], 'math class': []
    }

    for file_name in files:
        raw_data = np.loadtxt(os.path.join(path, file_name))
        for i in range(raw_data.shape[0]):
            exp_dataset['doppler bin'].append(raw_data[i, 0])
            exp_dataset['range bin'].append(raw_data[i, 1])
            exp_dataset['range'].append(raw_data[i, 2])

            # 8 complex channels
            ch = raw_data[i, 3:11] + 1j * raw_data[i, 11:19]

            # <<< УЛУЧШЕНИЕ: нормализация >>>
            if normalize == 'rms':
                ch = rms_normalize(ch)
            elif normalize == 'max':
                ch = ch / np.max(np.abs(ch))
            # else: 'none'

            exp_dataset['channels'].append(ch)

            # mb_metrix: берём реальные значения (обычно 3) + placeholder до 10

            exp_dataset['mb_metrix'].append(mb_pad)

            exp_dataset['azimuth'].append(raw_data[i, 22:24])
            exp_dataset['math class'].append(raw_data[i, 24])

    # Преобразование в numpy
    for key in exp_dataset:
        exp_dataset[key] = np.array(exp_dataset[key])
